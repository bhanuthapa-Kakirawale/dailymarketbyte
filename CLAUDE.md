# Daily Byte — project guide for Claude Code

Automated ~75s faceless YouTube Short: recap of the previous Indian (NSE) market session for traders.
Runs Mon–Fri 07:40 IST on GitHub Actions, uploads to YouTube. Informational only, never advice.

## Commands
- `python main.py --demo` — offline render with synthetic data (red "DEMO DATA - NOT REAL" badge). Use this to test any visual change.
- `python main.py` — real data, no upload. `--upload` uploads; `--force` ignores holiday/already-posted checks.
- `python upload.py --auth` — one-time YouTube OAuth (creates token.json).
- Verify a render: `ffprobe` duration must be 75.0s; extract frames with `ffmpeg -ss <t> -i out.mp4 -frames:v 1 f.png` and look at them.

## Architecture
- `main.py` — orchestration, captions text, scene durations (`BASE_DUR`, stretching via `durations()`), hook line, ticker items, YouTube metadata, demo data, safety checks.
- `market.py` — yfinance data (`history`, `get_movers`, `get_globals`, `get_sectors`), NSE website client (`NSE`, `nse_all_indices`, `fii_dii_nse`), technicals in `analyze()` (EMA20/50, RSI14, swing-based support/resistance, trendline, floor pivots).
- `news.py` — Google News RSS (free) + Gemini free API with Google Search grounding (`ask_gemini`). `ai_pass()` is the single combined Gemini call per run (market facts: GIFT Nifty/FII-DII/Brent/independent Nifty close, each validated by date + range; mover/Nifty move reasons; today's events) - kept as one request instead of three separate calls to stay under the free-tier RPD/grounding quota.
- `chart.py` — matplotlib chart saved as 3 aligned layers (0 axes, 1 candles, 2 levels) so video.py can animate the reveal. Layers must stay pixel-identical in layout.
- `video.py` — Pillow draws frames, piped as raw RGB to ffmpeg (imageio-ffmpeg binary). Each scene subclasses `Scene` with `key(t)` (cache key; quantize animation so frames can be cached) and `draw(d, L, t)` onto an RGBA layer. `Backdrop`, `Ticker`, header, captions, progress line composed in `render()`.
- `music.py` — procedural copyright-free track with swells at scene boundaries; rotates through 5 mood/tempo presets by calendar date (`_variant_index`) so consecutive sessions don't sound identical. `assets/music.mp3` overrides with one fixed track every day; `assets/music/1.mp3`..`5.mp3` overrides one real track per rotation slot. Playback volume is `config.MUSIC_VOLUME` (env `MUSIC_VOLUME`, default low ~0.22), applied in `video.render()`'s ffmpeg audio filter.
- `upload.py` — YouTube Data API v3 upload.
- `config.py` — all settings/env vars, colours, `fmt_in()` Indian number formatting.
- `core/` — canonical domain: `Observation` (what one source said, frozen), `Fact`, `ValidationResult`, `MarketReport`, `sources.py` (`SourceMetadata` + independence groups), the validator framework, and `content_safety.py`. No fetching, no drawing.
- `providers/` — acquisition layer (Phase 2). Wraps the existing `market.py`/`news.py` fetching; above this line everything is an `Observation` or a typed payload, never a raw provider dict. `yahoo.py` (+ `IndexSession`), `nse.py`, `news.py` (+ `NarrativeBundle`), `gemini.py`.
- `adapters/` — dict→Observation translation and `report_builder.build_report()`, which groups observations into validated facts and assembles the `MarketReport`.
- `presentation/` — `ReportPresentation` converts a `MarketReport` into the exact structures `video.py`/`chart.py` already accept. The renderer acquires nothing.
- `storage/` — SQLite historical index (Phase 3): `schema.py`, `migrations.py` (PRAGMA user_version), `repository.py` (`MarketHistory`, all SQL lives here). Defaults to `output/data/market_history.db`.
- `intelligence/` — Phase 4.1 deterministic historical context: `models.py` (`IntelligenceSnapshot`, eligibility policy), `history.py` (`HistoricalWindow`: exclusive cutoff, session semantics, bulk loading), `engine.py`, and the analysers (`market_context`, `flows`, `sectors`, `movers`, `volatility`). Reads the canonical report + `MarketHistory` only; writes `output/intelligence/`. See `docs/INTELLIGENCE.md`.
- `qa/` — deterministic post-render artifact checks (`check_video`, `write_qa_artifact`). No model involved. `probe_media`/`sample_frame_stats` are the one mockable media seam.
- `tests/` — `pytest`, fully offline (incl. an end-to-end run of the production branch with every network boundary stubbed). `python -m pytest tests/ -q`.
- `docs/` — ARCHITECTURE, DATA_MODEL, VALIDATION_RULES, SOURCE_PROVENANCE, MIGRATION_PLAN, CONTENT_SAFETY. Update these in the same commit as any architecture-affecting change.
- `core/content_safety.py` — Phase 1.1: deterministic (no Gemini) recommendation-language filter. `apply_content_safety()` in `main.py` sanitizes/drops mover reasons, the Nifty move summary, and event text before any scene or caption is built; `scan_publication()` re-scans every finalized caption/title/description immediately before upload and blocks it (never rewrites) if anything survives. See `docs/CONTENT_SAFETY.md`.

## Rules / decisions (keep these)
- No paid APIs. AI = Gemini free tier only (`GEMINI_API_KEY`, `GEMINI_MODEL`). Pipeline must still work with no key.
- An LLM is never a source of truth for a critical numeric market fact. Everything Gemini returns is `SourceType.AI`, and `core.validation` refuses to mark a critical metric (index/stock/sector moves, closes, levels, FII/DII, commodity, FX) `VERIFIED` when only AI observations back it — its ceiling is `PROVISIONAL`, and two agreeing Gemini answers are still `PROVISIONAL`. Passing a range check is NOT verification: a plausible wrong number passes. AI values reach `VERIFIED` only when an acceptable non-AI source independently agrees within tolerance. The rule lives in `CrossSourceValidator` so no new caller can skip it.
- Source authority is NOT source independence. `source_type` says how much one source's word is worth; `independence_group` says whether two readings are separate evidence at all. `CrossSourceValidator` counts INDEPENDENCE GROUPS, never observations — two Yahoo readings of one close are one witness, and two Google News items from one publisher are one witness. Never let a same-group pair produce `VERIFIED`. News groups by publisher (`news_source()`), not by the aggregator.
- The MarketReport is authoritative (Phase 2). It is built BEFORE anything is rendered, `check_publication()` makes `publication_ready` binding (an unfit report writes its JSON for diagnosis and renders nothing), and the renderer is fed from it via `presentation/`. The presentation invariant: IF A NUMBER IS DISPLAYED IN THE VIDEO, IT EXISTS IN THE MARKETREPORT — including the chart's candle series (`technicals.candles`). The adapter may reshape and format; it must never fetch or compute a market fact.
- Publication needs THREE gates to pass, none advisory: data QA (`report.publication_ready`), content QA (`core.content_safety`), video QA (`qa.check_video`). Persistence is a fourth precondition — if the run can't be recorded in history, it doesn't publish, because auditability is part of publication integrity. Failure never deletes artifacts: the video, metadata, report JSON and QA artifact are all preserved for diagnosis.
- JSON is the immutable per-run artifact; SQLite is a queryable index ACROSS runs that points back at those files (`json_artifact_path`). SQLite is never in the render path — a database problem must not be able to change what a video looks like. Persisting an existing `report_id` is a no-op (reruns must not duplicate canonical history); `publication_runs` always appends. Demo runs persist with `is_demo=1` and are excluded from every query by default.
- CANONICAL HISTORY IS IMMUTABLE once persisted. A report says what the market did; video QA, the final content scan and the upload result say what happened when we tried to publish it — the second must never rewrite the first. Per run the JSON is written ONCE and `save_report` is called ONCE; later verdicts go to `publication_runs` and the QA artifact. Never re-save the report JSON or call `save_report(replace=True)` from the pipeline — `replace=True` deletes and cascades, and exists only as a manual recovery tool (a test parses `main.py` with `ast` and fails if any call there passes it). Content safety has two stages: Stage A sanitises BEFORE the report is finalized (canonical, in `report.content_safety`); Stage B is the final publication scan (operational, blocks upload, never written back into the report).
- Historical intelligence is DETERMINISTIC and DERIVED. No LLM computes a streak, percentile, average, rank or classification — rules only, so the same report + database always gives byte-identical output. It acquires nothing (no provider/network/model; a test greps the package for those references) and mutates nothing (canonical JSON and rows are untouched). It never predicts, ranks securities or recommends. Enforce: the current session is excluded from its own comparison window; windows count TRADING sessions (weekends/holidays are not missing sessions); only `{VERIFIED, SINGLE_SOURCE}` facts are eligible (`ELIGIBLE_HISTORICAL_STATUSES`, centralised); relative volume compares only `definition_version == "2.0"` readings; a statistic defined as N sessions makes NO statement with fewer than N (never silently shorten); sector returns compound, never sum. STREAKS are continuity claims: they walk the canonical session spine (`get_recent_sessions`, independent of eligibility) and BREAK at any recorded session that is opposite/zero/missing/ineligible — never step over one to find another matching value. Calendar gaps (weekend/holiday/never-recorded) aren't on the spine so they can't break a run: a missing calendar day is not missing canonical evidence. Streaks say "consecutive recorded sessions"; cumulative flow keeps separate "available sessions" semantics. Relative-volume history dedupes to `(report_id, fact_id)` — counting observations would inflate the sample and rank. Every insight must carry sample size, lookback and supporting report/fact ids.
- Relative volume = current volume / mean of the PRIOR 20 sessions, current session excluded, `None` below 20 priors (definition_version 2.0; reports before Phase 3 used 10 and are NOT rewritten or backfilled — the definition travels on each observation's metadata). Don't silently compute over a shorter window and call it the same metric.
- Provenance is recorded at acquisition, never reconstructed downstream. `news.ai_pass` stamps each reason/event with the branch that produced it (`GEMINI`/`GOOGLE_NEWS_RSS`/`RULE_FNO_EXPIRY`/`NO_VERIFIED_CATALYST`), and `nse_all_indices` keeps NSE's market timestamp, which becomes `Observation.observed_at`. Don't reintroduce string-matching to guess where text came from — only the acquisition layer can still see it.
- Don't rewrite a legacy module to make new code prettier — adapt at the boundary. Provenance must be honest: an unavailable source is `None`, never a plausible guess.
- Daily Market Byte must never republish recommendation-style language (BUY/SELL/target price/stop loss/multibagger/etc.) picked up from a headline or brokerage note, even as a quoted fact. `core.content_safety` catches this deterministically (no Gemini — the guarantee must hold even when the AI layer is down) at two points: sanitize-on-generation for every mover reason/event/Nifty summary (BLOCKED text gets a neutral fallback, never the raw headline), and a final re-scan of every finalized caption/title/description immediately before upload that blocks publication (never rewrites) if anything unsafe survives. An attributed third-party rating ("MOFSL initiates BUY rating with target Rs 1,500") is neutralized to a fixed factual template rather than blocked outright, so ordinary brokerage-coverage news doesn't need to be dropped entirely.
- Accuracy over completeness: never post unverified numbers. Nifty close is cross-checked (NSE or Gemini) and the run aborts if >0.2% off. AI-sourced numbers must pass date + sanity-range checks or be hidden. A failed optional scene (global, fii, sector) is dropped and nifty/gainers/losers stretch so total stays 75s.
- Don't trust a single data source blindly just because the fetch succeeded - verified 2026-09-18: yfinance's `BZ=F` (Brent crude) ticker returned -5.28% vs an independently-reported -1.54% real move (a ~4x error, likely a thin/mismatched contract). DOW/NASDAQ/GOLD/USD-INR were cross-checked the same day and matched real sources closely, so this isn't a general yfinance problem - it's specific to that ticker. Brent is now sourced only via `news.market_facts()`'s Gemini-verified `"brent"` fact (same hide-if-unverified pattern as GIFT Nifty), not `market.GLOBALS`. Before trusting any new single-sourced number in this pipeline, cross-check it against an independent source first.
- Mover "reason" headlines (`news.explain_moves`) must be filtered by both the headline's RSS `pubDate` (`_same_day`) and a date pattern embedded in the title text itself (`_title_date_ok`) before being used - verified that recurring "Stocks to Watch Today, <date>:" listicle columns get republished daily with a fresh `pubDate` but keep a stale headline (e.g. crawled 19 Sep, title still says "Aug 3"), and Google News' relevance ranking put that ahead of genuinely same-day coverage. Never take `headlines[0]` un-filtered as a mover's reason.
- Never compute a day-over-day % change as `Close.iloc[-1] / Close.iloc[-2]` without first checking `iloc[-2]`'s DATE matches the expected previous trading session - verified 2026-09-18: yfinance's per-stock bulk download (`get_movers`) silently dropped 17 Sep entirely for ~25% of the Nifty100 universe (e.g. ADANIGREEN), so `[-2]` quietly pointed at 16 Sep, turning a 2-day move into a false 1-day one (shown +5.06%, real +4.73%). `market.get_movers`/`get_sectors`/`get_market`'s Bank Nifty calc now all take the actual previous session date (`analyze()`'s `prev_date`, from the Nifty index's own reliable calendar) and drop/skip anything whose own previous-close date doesn't match it, rather than risk a silently-wrong multi-day change. Apply the same date-alignment check to any new day-over-day calculation added to this file.
- yfinance's bulk `yf.download()` endpoint can return the latest session's row with Open/High/Low/Volume populated but `Close` still `NaN` - verified 2026-09-22: effectively the whole NIFTY100 universe showed this for 21 Sep, still unresolved several minutes (and multiple retries) after that session's close, i.e. this can be a persistent Yahoo-side backfill lag, not just a few-second blip. `_clean()`'s `dropna(subset=["Close"])` correctly drops that unusable row, which silently pushed every stock's "latest row" back to the prior session and made `get_movers` find zero movers for `recap_date`. `get_movers` now distinguishes this signature (the row for `recap_date` exists pre-dropna, just with a NaN Close) from a stock with no data at all, and retries the whole batch fetch up to 2 more times with a 30s/60s wait before giving up - this fixes a short-lived lag but NOT one that persists for minutes, in which case the `RuntimeError` is correct (never publish gainers/losers built from an incomplete close) and the right recovery is to re-run later or let the next scheduled cron pick it up once Yahoo has backfilled, not to add more in-process retries.
- Skip upload if yesterday was a market holiday (latest session != previous weekday).
- Keep the on-screen and description disclaimer ("For information only - not investment advice"). No buy/sell language, no predictions in captions (SEBI).
- Layout must stay in the Shorts safe zone: content between y≈340 and 1195, captions box y 1215–1475, nothing important on the far right below y≈1100. Canvas 1080x1920, 30 fps. The strip below the disclaimer (y≈1524–1920) is left empty on purpose - reserved for the YouTube Shorts app's own UI overlay (title/channel/audio-track/like-comment-share). Don't add content there - this is a financial/informational video, not a music-video style visualizer.
- `SECTION_Y` (video.py) is load-bearing: `NiftyScene` hardcodes its chips row (y=446) and chart paste (y=508) relative to it rather than deriving them, so don't shift `SECTION_Y` without re-checking the chart still fits above y≈1195.
- Text must fit: use `fit()`, `ellipsize()`, `wrap()`; reasons are clipped to ~13 words.
- Rupee sign via `video.RS` (falls back to "Rs " if the font lacks ₹).
- Demo data must use placeholder names (STOCK-A...) so it can never be mistaken for real data.

- "Events today" (`news.todays_events`) must be specific, named events only - IPO opens/GMP, company results/corporate actions, RBI/govt decisions, Fed/global data - never generic daily "roundup" columns (Ahead of Market, Stocks to Watch, Market Wrap, etc., which just reuse the same catch-all title every day and aren't actual events). Both the Gemini prompt and the no-key fallback (`_fallback_events`, targeted per-category queries filtered through `_GENERIC_ROUNDUP`) must keep excluding those.

## Known limitations
- NSE website often blocks cloud IPs (GitHub runners) → FII/DII and sector data fall back to Gemini / Yahoo.
- GIFT Nifty only via Gemini search (hidden if unverifiable).
- YouTube uploads are private until the Google Cloud project passes the API audit. OAuth consent screen must be "In production" or tokens expire after 7 days.
- GitHub cron can start 5–20 min late; runs take ~4–6 min.
- Nifty 50 fallback constituent list in market.py goes stale; the live NSE CSV is preferred.
- Gemini's `generateContent` (`news.ask_gemini`) intermittently 404s/503s even with a valid key/model/project - confirmed as a known, unresolved server-side Gemini API bug (Google's own developer forum, Sep 2026 - same request sometimes succeeds, sometimes 404s, across different projects/keys). Not a sign the model name or key is wrong. `ask_gemini` retries those (5x, capped backoff) and logs the response body on failure; if it still fails, `ai_pass` already degrades gracefully - AI-only facts (GIFT Nifty, Brent, verified FII/DII) are simply omitted and reasons/events fall back to the non-AI paths, never a guess. This is by design, not a bug to "fix" further without a real Google-side change.
- A Gemini 429 ("You exceeded your current quota...") is a different failure from the 404/503 bug above - it's the free-tier RPD/RPM (or grounding) quota exhausted, not a transient server hiccup, so retrying within the same run can't succeed. `ask_gemini` fails fast on 429 (no backoff loop, unlike 404/503) straight to the same graceful no-AI-facts fallback. `news.ai_pass()` already merges what used to be three separate Gemini calls per run (`market_facts`/`explain_moves`/`todays_events`) into one request to stay under the free-tier quota; if 429s still recur daily, the remaining fix is upgrading the API plan/billing, not retrying harder or adding calls back.
